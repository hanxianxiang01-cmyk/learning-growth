V1.4 Renderer Development Task Breakdown
版本： V1.4-P0定位： Renderer Semantic Completion 开发执行基线上游基线： 《V1.4 Renderer Semantic Completion Matrix》配套基线： 《V1.4 Renderer Semantic Completion → Development Gap Matrix》范围： 19 个 V2 Renderer + Renderer Runtime + Contract + Evaluator + Evidence + Diagnosis + Vertical Gate目标： 将现有 Renderer 从“组件存在”推进到“可接入、可交互、可评估、可诊断、可验收”的 V2 Renderer。
1. 文档目的
本文件不是架构设计文档，而是 V1.4 开发任务拆解表。
开发人员应以本文件回答以下问题：
当前要开发什么；
修改哪个模块；
依赖哪个 Contract；
Renderer 如何接收 Task；
用户操作如何形成 Semantic Event；
Response 如何进入 Renderer；
Evaluator 如何判断结果；
Evidence 如何生成；
Diagnosis 如何消费 Evidence；
如何进入 Vertical Gate；
什么条件下才能标记完成。
2. V1.4 开发总原则
2.1 不允许以“页面完成”作为 Renderer 完成标准
以下情况均不能标记 Renderer Complete：
页面能够打开；
UI 能够点击；
能够输入答案；
能够显示正确/错误；
本地 mock 数据可以运行；

24. V1.4 开发管理结论
当前 V1.4 不应该再以：
“还有哪些页面没有开发？”
作为主要管理问题。
应该改成：
“19 个 Renderer 的 Semantic Completion 是否全部闭环？”
因此开发管理层级固定为：
Layer 1
Renderer Runtime
↓
Layer 2
Renderer Contract
↓
Layer 3
19 Renderer
↓
Layer 4
Evaluator / Evidence / Diagnosis
↓
Layer 5
Five Vertical Gates
↓
Layer 6
V2 Contract Freeze
↓
Layer 7
Release QA
V1.4 的 P0 开发完成定义：
不是 19 个 Renderer “都有页面”，而是 19 个 Renderer 都能在统一 Contract 下完成 Task → Interaction → Response → Evaluation → Evidence → Diagnosis → Next Task 的可验证闭环。
因此，本文件可以直接作为 V1.4 Frontend Development Backlog 的母表。后续开发人员不应再自行解释“Renderer 完成”的含义；所有开发、Code Review 和 QA 均以本 Breakdown + Semantic Completion Matrix + Vertical Gate 为准。
