# V1.4 前端实现说明

## 1. Frozen chain

```text
Renderer Registry
        ↓
Workspace API
        ↓
TaskUISchema V1.4 extensions
        ↓
Structured Response V1.4 extensions
        ↓
Diagnosis / Hint normalization
        ↓
P0 cross-contract boundary
```

## 2. Renderer Registry

前端以 `renderer_id` 作为渲染入口，当前内置：

- `number-input`
- `object-counter`
- `bar-model`
- `number-line`
- `unsupported`

任务未声明 `renderer_id` 时，按兼容规则由 `kind + visual.type` 推导；未知 renderer 安全降级，不白屏。

42 个能力节点不在前端写死为 42 个页面。能力节点只需要通过后端 TaskUISchema 绑定 renderer/capability profile。

## 3. Workspace API

`WorkspaceProvider` 对外提供：

- `state`
- `commit`
- `undo`
- `reset`
- `applyHint`
- `emitInteraction`

Workspace 只维护数学操作表征，不计算 Mastery、Diagnosis 或 Curriculum 决策。

## 4. TaskUISchema

在 V1.3 基础上增加可选字段：

```json
{
  "renderer_id": "bar-model",
  "interaction_capabilities": ["answer_input", "resize", "undo", "reset"],
  "renderer": {
    "renderer_id": "bar-model",
    "version": "1.0",
    "capability_ids": ["answer_input", "resize", "undo", "reset"]
  }
}
```

兼容层继续允许旧后端只返回 `kind / visual / tools / response_schema`。

## 5. Structured Response

新增受控交互轨迹：

```json
{
  "schema_version": "1.0",
  "answer": "8",
  "representation": {},
  "interaction_events": [
    {
      "event_id": "...",
      "event_type": "jump",
      "occurred_at": "2026-09-30T...Z",
      "task_instance_id": "...",
      "renderer_id": "number-line",
      "capability_id": "jump",
      "target_id": "8"
    }
  ]
}
```

交互事件只用于记录前端行为，不允许改变 Mastery/Diagnosis。

## 6. Diagnosis / Hint

HTTP Adapter 对 `AttemptResult.diagnosis` 与 `HintResponse.ui_action` 做结构归一化。

- `E01~E07` 等教育诊断码保持业务载荷，不作为 HTTP error。
- 前端不根据 diagnosis 自己推导能力等级。
- `ui_action` 只能进入 Workspace 的受控 action 集合。
- Hint 不得直接执行路由、脚本或答案提交。
