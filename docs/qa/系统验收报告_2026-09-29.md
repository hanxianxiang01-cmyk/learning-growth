### 2.2 API 端到端实测 —— 全链路通过 ✅

用 httpx ASGI 直连 FastAPI，走通完整学习闭环：

| 步骤 | 请求 | 结果 |
|------|------|------|
| 1. 画像 | `GET /v1/children/{id}/profile` | 200，developing 按依赖链排序 ✅ |
| 2. 能力 | `GET /v1/children/{id}/abilities` | 200，7 能力 ✅ |
| 3. 开会话 | `POST /v1/learning/sessions` | 201 ✅ |
| 4. 选题(指定能力) | `POST /v1/learning/tasks/next` + `ability_id=app_rel` | 200，正确分流 objects ✅ |
| 5. 选题(换能力) | `ability_id=app_strat` | 200，正确分流 number-line ✅ |
| 6. 作答(答错) | `POST /v1/learning/attempts` | 200，correct=False + 诊断 E04 ✅ |
| 7. 提示 | `POST /v1/learning/hints` | 200，返回 ui_action=align_groups ✅ |
| 8. 作答(答对) | 填正确答案 | correct=True + next_action=NEXT_TASK ✅ |
| 9. 结果 | `GET /v1/learning/sessions/{id}/result` | 200，计数正确 ✅ |

**关键验证点全部命中：**
- ✅ 挑战入口 → 能力分流生效（app_rel→objects，app_strat→number-line）
- ✅ 判分正确（8 比 5 多几 = 3）
- ✅ 答错诊断生成（E04 modeling gap）
- ✅ Hint 返回 WorkspaceUiAction（align_groups），能驱动前端交互工作台

> ⚠️ **发现点 1（提示级）**：不指定 `ability_id` 时，默认选题按 level 升序选到 `app_cond`（条件识别）D1 题，`visual=None`（纯 number 读题题）。这符合内容设计（读题题无需 manipulatives），但意味着「无指定能力的兜底路径」会优先分到读题/条件类，而非关系/策略类。若产品预期是「兜底默认练关系」，需调整后端候选排序。

## 六、建议下一步

1. **【P1 建议】** 同步前端 mock 题库：把 `mock.ts` 的 `taskBank` 替换为与后端 50 题一致的变式题（至少每类交互各 2~3 题），让 mock 模式体验与 http 模式一致。
2. **【P2 可选】** 确认默认选题策略：无 ability_id 时是否应优先 `app_rel`（数量关系）而非 `app_cond`。
3. **【P2 可选】** 浏览器级 UI 回归：起 `npm run child:dev`，用浏览器实测三个 manipulatives（拖拽/线段调节/数轴跳格）的渲染与提交。
4. **【治理】** 内容团队在 Excel 中标注 `draft`，当前以 `published` 入库；如需「仅发布 approved 题」的开关，可在 seed 中加过滤。
